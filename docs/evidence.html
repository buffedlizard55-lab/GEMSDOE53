GEMSDOE29 leakage — formal diagnosis (Kaufman et al.)

Full write-up: docs/leakage-review.md. In one line: the feature log1p(min(distance-to-catalogue, 60)) was computed from the full label raster while training labels were the catalogue's own pixels, so the feature is exactly 0 on every positive (our X4 positive control measures separability 1.000 for this construction) — target information that cannot legitimately exist for an unmapped fault at prediction time. Fix = learn–predict separation: every catalogue-derived feature is recomputed from visible faults only, which is what H8 does (X4 verifies it).

Limitations (31 items)

  • L-24: Compute: 2 vCPU, 3.9 GB RAM, no GPU. The shared template's CNN pipeline was not run; every model here is a gradient-boosted classifier on 19 bands (plus H1 where stated).
  • L-25: One negative-sampling seed (53) and one model configuration. Fold CIs describe fold-to-fold spread only, not seed-to-seed Monte-Carlo variance.
  • L-26: Uniqueness is checked against the GEMSDOE* repositories as they stood on 2026-10-08 (tips at fetch time). Later submissions by other teams are not covered.
  • L-27: The protocol's raw overlap gate cannot be passed by any placement on the rebuilt registry (IR-53-46). Until the user redefines the gate, no candidate from this repository can be labelled OK to submit.
  • L-28: H8 holdout numbers are HOLDOUT-DTI (gems53.core.dti v1.0.0 parity + shared template GtContext; withheld catalogue segments; 5 folds seed 53; 60,988 catalogue px; 95% t-CI df 4). None is ORGANIZER-CONFIRMED; no file from this repository has an organizer score.
  • L-29: IR-53-42 applies to every H8 claim: the holdout truth is the visible catalogue's withheld segments; the competition scores faults absent from the catalogue. The >2 px prune makes the emission organizer-aligned (no credit is sought on mapped faults), but whether tip/relay corridors cover the organizers' unmapped faults is untested.
  • L-30: Budget rule chose N=80,000 (pooled 0.1663) over N=44,090 (0.1651) by +0.0012 HOLDOUT-DTI, which is inside the fold CI. On the organizer metric the extra 36k dots double the FP mass at alpha=0.2 for unmeasured benefit (holdout saturates). Both dot counts are shipped in the receipt so the selector can choose; the primary file follows the pre-registered rule (N=80,000).
  • L-31: The [0,1] form rejection root cause (IR-53-50) is inferred from the exact error text plus the template's documented identical rejection; we cannot log in to the DrivenData form to re-test (no auth). The zeros variant is the pattern of organiser-scored ledger rows, which is strong but not proof for this form version.
